# 行为分析规则参考

## 1. 字段映射

| 输出字段 | API 字段 | 原业务数据来源 | 说明 |
|------|------|------|------|
| 玩家ID | `data.uid` | 用户:游戏用户管理 | 直接透传 |
| 账号创建时间 | `data.cTime` | 用户:游戏用户管理 | 直接透传 |
| 最后登录时间 | `data.lTime` | 用户:登录历史管理 | 直接透传 |
| 当前游戏等级 | `data.lvl` | 用户:游戏用户管理 | 直接透传 |
| 剩余元宝 | `data.dmd` | 用户:游戏用户管理 | 直接透传 |
| 充值次数 | `data.rchgCnt` | 记录:充值记录信息 | 为累计字段，和当前返回数据内笔数可能不同 |
| 登录记录条数 | `data.analysisMetrics.counts.loginRecordCount` | 服务端纯计算汇总 | 不再从 loginList 自行计数 |
| 充值记录条数 | `data.analysisMetrics.counts.rechargeRecordCount` | 服务端纯计算汇总 | 不再从 rchgList 自行计数 |
| 缺失充值时间数 | `data.analysisMetrics.counts.rechargeRecordMissingTimeCount` | 服务端纯计算汇总 | 不再从 rchgList 自行判断 |
| 登录小时分布 | `data.analysisMetrics.login.hourBuckets` | 服务端纯计算汇总 | 不再从 loginList 自行聚合 |
| 充值小时分布 | `data.analysisMetrics.recharge.hourBuckets` | 服务端纯计算汇总 | 不再从 rchgList 自行聚合 |
| 充值关键时段分布 | `data.analysisMetrics.recharge.keyWindowBuckets` | 服务端纯计算汇总 | 不再从 rchgList 自行聚合 |

## 2. 分析窗口

- 分析范围以接口实际返回的数据为准，由下游服务控制。
- 当前 skill 不自行传递或裁剪 `近7天`、`近30天` 等时间窗口。
- 若返回结果中无数据，不得用累计字段强行推导时段分布。

建议口径：

- 充值记录为空：`当前返回数据中未发现充值记录。`
- 登录记录为空：`当前返回数据中未发现登录记录，无法进行登录时段分析。`
- 登录和充值均缺失：`当前接口返回的行为数据不足，暂无法形成有效判断。`

## 3. 登录分析规则

1. 依据 `data.analysisMetrics.login.hourBuckets` 进行阈值判断与连续小时合并，skill 不再从 `loginList` 自行计数。
2. 仅展示单小时登录次数 `>= 20` 的时间段。
3. 连续小时段可合并展示，如 `22:00-24:00`。
4. 若高频登录时段分散覆盖多个时段、没有明显主时段，可统一表述为：`玩家近期登录时间覆盖全天。`
5. 若无任何小时达到展示阈值，输出：`当前返回数据中未发现达到展示阈值的高频登录时段。`

推荐表述：

- `玩家近期登录时间主要集中在22:00-24:00。`
- `玩家近期登录时间主要集中在12:00-13:00、22:00-24:00。`
- `玩家近期登录时间覆盖全天。`

## 4. 充值分析规则

仅关注以下关键时段（已由 `data.analysisMetrics.recharge.keyWindowBuckets` 预聚合）：

| 时段 | keyWindowBuckets 键 | 说明 |
|------|------|------|
| `08:00-09:00` | `08:00-09:00` | 上学时间 |
| `12:00-13:00` | `12:00-13:00` | 午休时间 |
| `22:00-24:00` | `22:00-24:00` | 夜间时间 |

规则：

1. 依据 `data.analysisMetrics.recharge.keyWindowBuckets` 判断关键时段是否集中，skill 不再从 `rchgList` 自行聚合。
2. 充值分析只写摘要，不罗列逐笔订单、金额、分钟级明细。
2. 仅在关键时段存在明显集中时，使用“主要集中在”表述。
3. 若无明显集中，输出：`充值时间未明显集中在上学/午休/夜间关键时段。`
4. 当需要写笔数时，优先写“当前返回数据中”笔数，避免与累计 `rchgCnt` 混淆。

推荐表述：

- `当前返回数据中共充值5笔；充值时间主要集中在22:00-24:00时间段。`
- `当前返回数据中共充值3笔；充值时间主要集中在12:00-13:00时间段。`
- `当前返回数据中共充值2笔；充值时间未明显集中在上学/午休/夜间关键时段。`

## 5. 综合判定规则

综合判定只允许基于“登录时段”“充值时段”“数据完整性”来落结论，不做真实年龄判断。

### 5.1 推荐结论模板

数据较充分且未见明显重合时：

`根据账号登录时间、充值时间及游戏行为特征分析，当前未见明显与未成年人常见游戏/充值时段重合的行为特征，现有证据不足以支持未成年人充值判断，如需进一步核查需提供更多证明材料。`

存在部分重合特征时：

`根据账号登录时间、充值时间及游戏行为特征分析，该账号存在部分与未成年人常见游戏/充值时段重合的行为特征，但以上仅为行为特征分析，无法直接判定玩家真实年龄，建议结合监护关系、支付凭证等材料进一步核查。`

数据不足时：

`根据当前接口返回数据，登录或充值行为数据不足，暂无法形成有效行为特征判断，如需进一步核查需补充更多证明材料。`

### 5.2 降级原则

- 只有充值数据、没有登录数据时：可以提示“存在部分重合特征”，但**不得**直接下强结论。
- 只有单次或少量充值记录时：只描述时段，不放大解读。
- 没有聊天记录时：保持默认文案，不得补写“疑似儿童”“自述年龄”等内容。

## 6. 禁止表述

以下措辞默认禁止：

- `冲动消费`
- `偷玩`
- `缺乏消费理性`
- `极其异常`
- `典型未成年模式`
- `符合未成年人夜间偷玩并消费的特征`
- `可以判定为未成年人充值`

以下推断默认禁止：

- 没有日历依据时写 `周末/假期`
- 没有登录数据却把结论建立在“登录行为明显异常”上
- 用逐笔金额大小直接推出玩家心智或年龄

日期相关补充规则：

- 写”周几”时，只看 `weekdayCn`
- 写”节假日”时，必须 `isHoliday=true`
- 写”调休补班”时，必须 `isAdjustedWorkday=true`
- 若字段缺失，只能降级为不引用日期语义，不能自行推断

## 7. 对样例输出的纠偏

原样例常见问题：

1. 充值部分过度展开，写入逐笔订单、金额和分钟级细节，不符合“仅展示关键行为特征”的要求。
2. 综合判定越界，把行为分析写成年龄倾向判断，并加入 `冲动消费`、`缺乏消费理性` 等主观措辞。
3. 日期对应的”周几/节假日/调休”由 AI 自行推断，没有引用接口返回的日历增强字段。

更合规的写法应类似：

```text
玩家ID：623100001
账号创建时间：2025-11-12 11:04:41
最后登录时间：2026-04-01 10:56:42
当前游戏等级：50级；剩余元宝：76483
充值情况：
当前返回数据中，充值时间主要集中在22:00-24:00时间段。
登录情况：
当前接口未返回登录记录数据，无法进行登录时段分析。
聊天记录情况：
当前聊天记录中未发现涉及年龄相关的聊天信息。
综合判定：
根据当前账号充值时间特征分析，存在部分与未成年人常见夜间充值时段重合的行为特征；但由于缺少登录行为数据，以上仅为行为特征分析，无法直接判定玩家真实年龄，建议结合更多证明材料进一步核查。
```
